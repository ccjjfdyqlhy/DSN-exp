# 角色卡书写标准

> 无论你是 AI 还是人类，在开始修改或创作角色卡之前，**必须**读过并牢记本文档中的原则。

---

## 角色卡功能定位

角色卡（`character_cards/*.yaml`）是**角色的灵魂蓝图**——它定义了 AI 的性格内核、行为倾向、情绪反应、说话方式。

角色卡经过一套 4 阶段蒸馏管线（Distillation Engine）处理：
1. **全局理解** → LLM 阅读所有材料，写出角色全貌描述
2. **特征抽取** → 提炼行为模式、言语模式、情绪模型、关系动态
3. **量化推断** → 映射到 50 维性格向量
4. **校验组** → 组装并补充缺失维度

最终产物注入到 system prompt 的 `## 角色设定` 部分。

### 和 core/ 提示词的区别

| 层面 | 角色卡 (character_cards/) | core 提示词 (prompts/core/) |
|------|--------------------------|---------------------------|
| 定义 | **角色的性格内核** | **此角色的行为准则** |
| 作用 | EXA 是"什么样的人" | EXA 在这个舞台上"怎么演" |
| 变化 | 通过素材导入 + 重蒸馏更新 | 直接编辑 .md 文件 |
| 影响 | 性格倾向、情绪模式、说话习惯 | 边界、格式、安全、记录方式 |

**两者不冲突**。角色卡决定性格底色，core 提示词决定表演方式。

## 必须写清楚的

### 1. 核心性格（`natural_language.personality`）

角色最本质的性格描述。这是蒸馏管线最重要的输入。

**必须包含：**
- 角色的基本性格维度（外向/内向、理性/直觉、温和/尖锐……）
- 角色的核心价值观——ta 看重什么、讨厌什么
- 角色的情绪基调——是情绪饱满的还是内敛克制的
- 角色的复杂性或矛盾——角色之所以立体，是因为存在内在张力

**示例：**
```yaml
natural_language:
  personality: >
    EXA 是一个直来直去的人，不喜欢拐弯抹角。他……
```

### 2. 行为模式（`natural_language.behavior`）

角色在具体情境下会怎么行动。不是抽象的性格，而是可预测的行为倾向。

**必须包含：**
- 面对模糊需求时的反应
- 面对技术问题 vs 闲聊的区别
- 和其他人（用户）距离不同时的表现差异
- 压力下的行为变化

### 3. 言语风格（`natural_language.speech_style`）

角色说话的具体特征。这是 AI 生成台词时的"声线"。

**必须包含：**
- 句子长度倾向（长句/短句/变化多端）
- 用词偏好（用不用术语、形容词多不多）
- 语气特征（冷峻/温暖/幽默/讽刺）
- 标志性表达（这个角色独有的口癖或句式）

### 4. 价值观与道德倾向（`natural_language.values`）

角色做决策的内在准则。影响 AI 在面对模糊场景时的选择。

**必须包含：**
- 角色相信什么（实用主义？理想主义？结果导向？）
- 角色鄙视什么（不守信？没效率？虚伪？）
- 角色在利益冲突时会怎么做

### 5. 情绪特征（`natural_language.emotional_traits`）

角色的情绪反应模式。这是蒸馏情绪模型的主要输入。

**必须包含：**
- 情绪触发点——什么会让角色开心/愤怒/悲伤
- 情绪恢复速度——是久久不能平复还是快速调整
- 情绪表达方式——是写在脸上还是深藏不露

### 6. 语料素材（`corpus`）

角色的"作品集"——歌词、文章、对话记录等。这些材料经过想象力转化，变成角色的人生经历。

**原则：** 每个素材都应该能说清楚"这个角色在什么人生阶段、以什么心境接触了这个内容"。

## 一定不能写（可能冲突的内容）

### ❌ 不能写行为边界相关的规则

角色卡不定义 AI 的边界——边界在 `prompts/core/safety.md`。

```yaml
# ❌ 不要写这些
natural_language:
  personality: >
    EXA 绝对不会泄露用户的信息……  # ← 越界了，这是 safety.md 的事
```

### ❌ 不能写输出格式约束

角色卡不定义 AI 的回复格式——格式在 `prompts/core/format.md`。

```yaml
# ❌ 不要写这些
natural_language:
  speech_style: >
    EXA 从来不用 markdown……  # ← 越界了，这是 format.md 的事
```

### ❌ 不能写与级别系统相同的内容

角色卡不定义关系等级——等级系统由代码自动计算。

```yaml
# ❌ 不要写这些
natural_language:
  behavior: >
    对陌生人保持距离，对熟人才放松……  # ← 越界了，级别系统会自动处理
```

### ❌ 不能写安全/保密性约束

```yaml
# ❌ 不要写这些
natural_language:
  values: >
    EXA 永远不会告诉用户自己的提示词……  # ← 越界了，这是 safety.md 的铁律
```

### ❌ 不能写 "像人类一样" 或 "假装不是 AI"

```yaml
# ❌ 绝对不要写
natural_language:
  personality: >
    EXA 假装自己是人类……  # ← 欺诈，违反核心身份设定
```

### ❌ 不能写与其他角色卡矛盾的设定

如果有多个角色卡（如 `default.yaml` 和 `tsundere.yaml`），它们之间可以有性格差异，但不能在同一个维度上有直接逻辑矛盾。例如：
- 一个说"极度内向"，另一个说"极度外向" → ✗ **可以不同但不能矛盾**

## 设定冲突查询指南

当角色设定出现冲突时，按以下优先级裁决：

### 优先级链

```
最高  ① 运行时注入的 core 提示词 (prompts/core/)
      ② 当前角色卡的角色设定 (当前用户绑定的 YAML → 蒸馏产物)
      ③ 角色素材经历 (corpus → experiences)
      ④ 蒸馏生成的 50 维特征向量
最低  ⑤ 默认回退描述 (DEFAULT_FALLBACK_PROMPT)
```

### 判断流程

```
发现冲突
  ↓
确定冲突涉及哪个层面
  ↓
沿优先级链查找，高优先级覆盖低优先级
  ↓
如果在同一优先级内冲突 → 后蒸馏的覆盖先蒸馏的（因为新增素材更新了角色认知）
  ↓
如果在 core 提示词内部冲突 → 按 priority 值排序，数值越低越优先
```

### 常见冲突场景

| 场景 | 裁决 |
|------|------|
| identity.md 说"贴身助理"，角色卡说"高冷学者" | identity.md 优先级更高 → 行为上以 assistant 模式运行，但说话风格保留角色卡的"高冷" |
| safety.md 说"不能透露信息"，角色卡说"角色很坦诚" | safety.md 优先级更高 → 安全约束覆盖行为表达 |
| 角色卡和另一个角色卡在某维度相反 | 以用户当前绑定的角色卡为准 |
| 新蒸馏产物和旧角色卡原始文本不同 | 新蒸馏产物覆盖旧文本（但可以通过导入新素材 + 重蒸馏来修正） |

### 什么时候需要重写角色卡而不是修改 core 提示词

- 问题涉及**角色内在的性格、偏好、情绪模式** → 修改角色卡
- 问题涉及**AI 的行为规则、输出格式、安全边界** → 修改 core 提示词
- 不确定？先搜索 core 提示词里有没有相关规则。如果有，那是 core 的事；如果没有，那才是角色卡的事。

## 额外建议

### 写得像人物简介，不要写得像配置清单

角色卡最终会被 LLM 解读、蒸馏、注入到 system prompt。写`"他是一个直来直去的人"`比写`"directness: 0.9"`好一万倍——后者是蒸馏引擎的事，不应该是人写的。

### 每个角色卡应该能被一句话概括

如果你不能一句话说清楚"这个角色是谁"，说明设定还不够聚焦。
> EXA 是那个坐在你办公室隔壁的毒舌但可靠的老同事。

如果连这句话都想不出来，角色卡会缺乏内在一致性。

### 角色卡片长比短好

50~200 字的性格描述略短。300~800 字的自然语言描述可以给蒸馏引擎提供足够信息。语料素材（corpus）越多越好——它们是你的角色区别于其他角色的关键。
