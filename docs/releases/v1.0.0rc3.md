# v1.0.0rc3

The third release candidate. It closes the six items the rc0 roadmap listed
as still missing: the control plane, the workflow and planner kernels, agent
identity with delegation, the sampling loop with bad case feedback, the
scheduler and the workspace isolation, and the audit trail that the business
cannot delete.

## What it delivers

- **A control plane.** `infra/control/` holds the agent artifact (one
  declaration, consumed in many places), its lifecycle (a release must
  carry a gate report with verdict=pass), an artifact store that refuses a
  conflicting (id, version), a cost ledger that attributes the cost by
  session, agent, tool and model, and the adoption of a runtime you bring
  yourself.
- **Agent identity and delegation.** `infra/control/identity.py` holds the
  identity and the delegation chain: the scope of a child must sit inside
  the scope of its parent, a wider scope is refused, and every delegation
  is audited.
- **Two more kernels.** `harness/kernel/workflow.py` runs a DAG with
  parallel branches, reverse order compensation and cycle detection.
  `harness/kernel/planner.py` runs a structured plan with bounded
  replanning and a compensation per step.
- **The sampling loop.** `infra/eval/sampling.py` samples the traces
  deterministically. `infra/eval/badcase.py` takes a bad case from intake
  to label to the hard case regression set.
- **The scheduler and the isolation.** `infra/runtime/scheduler.py` leases
  a deployment with a heartbeat and a fencing token, so an instance that
  lost the lease cannot write any more. `infra/runtime/isolation.py`
  describes a workspace as {fs, net, secret}.
- **An audit trail that cannot be deleted.** `ToolGuard` takes an `audit`
  port, and the SDK and the CLI write the audit events into the separate
  store. A failure of the audit backend does not block the call.
- **The tool discovery, the policy loader, the grounding and the memory
  layers**, with the shipped policy files in `policies/` and the sample
  agents in `agents/`.

## Try it

```bash
pip install "aicf-core==1.0.0rc3"
aicf artifact list
aicf run --artifact agents/study.yaml
```

## What is still missing

The isolated sandbox (a container or a micro vm). The restricted and the
namespaced backends are there, the strong one is not.

Three things stay deliberately out of scope, and they are deployment
matters rather than debts: the cross machine orchestration (the lease and
the takeover protocol are pinned, where the orchestrator starts the process
is not), the transport of the runtime you bring yourself (the protocol is
pinned, the channel is not), and the inter process queue for the sampling
(the in memory queue is enough until the traffic says otherwise).

Personalization is there as an interface only: the automatic write of a
profile needs a privacy review, so only the authorized injection ships.
