## 新增

### `aicf init <name>` —— 空白脚手架

新建一个空文件夹、跑一条命令，得到一套**写好了接入点、但没有业务**的骨架：

```
my-agent/
  agent.py          # create_agent(...) 已接好，工具表留空
  tools/            # 一个示例工具 + 接入点注释
  policies/         # 默认策略：默认拒绝 + effectful 要审批
  traces/           # .gitkeep
  README.md         # 这个骨架怎么跑、往哪填
  pyproject.toml
```

每个接入点都是**能直接跑的最小接线**，不是 TODO 列表。
`aicf init demo` 之后 `aicf tool list` 就能看见自己注册的工具。

### 语音交互层 `aicf/harness/voice/`

流式逐句朗读（不等整段生成完）、假语音过滤、感知模式（连续通话、沉默=在听）。
此前这些能力只存在于应用层，框架层没有 —— 框架**只有**语音的资源管理
（`aicf/infra/resources/`：ASR / TTS / VLM 的本地资源池），没有交互层。

### 记忆溯源 `aicf/harness/memory/provenance.py`

Source（不可变证据）→ Artifact（可修订解释）两级模型，带 revision 链、
**证据闸门**（`EvidenceGate`）与**披露矩阵**（`DisclosureMatrix`）；
记忆写入进审计轨。

这是「持久记忆**可审计**」这根支柱的实现。此前 `MemoryEntry` 只有
text / role / meta / timestamp —— 没有来源、没有修订、没有证据、没有作者。

### 资源档位 `resident` / `balanced` / `eco`

- `resident` —— 显存换延迟，永不自动卸载。第一次语音请求的延迟 == 常驻延迟。
- `balanced` —— 默认档，向后兼容，各资源按自己的配置来。
- `eco` —— 显存优先，闲置 10 分钟就卸（decision/vlm 5 分钟）。

显式解决「随时可用」与显存的冲突。此前是单一策略（闲置就卸），
和「随时可用」直接打架。

### `aicf learn` 与 `benchmarks/`

轨迹 → 数据集 → 判官 → 晋级的闭环，以及**可复现的基准数字**：

```
memory_compaction_ratio   记忆压缩比            （实测 3.35）
fault_suite               崩溃恢复成功率        （实测 1.0，46 passed / 0 failed）
```

### 离线评测集 `offline.yaml`

零 API key 验证 `run → trace → eval → gate` 链路，**6/6 通过、闸门判定「通过」**。

与 `basic`（40 case，质量回归，需真模型）**刻意分开** ——
不把「链路坏了」和「模型退步了」混进一张报告，排查时永远是灾难。

## 修复

### 评测集与注册表脱节

随包数据集里 27 条工具断言有 26 条指向**注册表里不存在的工具名**
（`fs.read` / `calc.eval` / `web.search` …），而注册表里叫
`file.read` / `web.fetch`。

后果不是「用例失败」，而是**用例永远不可能通过**，且失败原因会被误读成
「模型没调用工具」—— 「可度量」这根支柱是空的。

现在由 `aicf/infra/eval/tool_vocab.py` 的 `TOOL_NAME_ALIASES` 统一绑定，
**评测集本身一个抽象名都没改**（换实现时只改词表右边那一列）。
另有 6 条断言了当前实现里不存在的工具的用例，已改为断言**结果**而非工具名。

### 回声算通过

桩模型把输入原样吐回来时，若期望内容恰好出现在输入里
（输入「200 的 10% 是多少」、期望输出含「20」），`output_contains` 会
**假通过** —— 一个什么都没答的模型拿到了通过。
评测器现在识别「输出 = 输入（可带 `[stub]` 标记与标点）」这一种回声，
判它不满足 `output_contains` / `output_matches`。

### CI 的 eval 作业只跑 `--help`

1.0.0 之前那一步是 `eval --dataset basic --help`，于是「随包数据集能不能真的用」
从来没被验证过 —— **这正是坏包能连发 6 个版本而没人发现的原因**。
现在真跑一次 eval 与 gate，断言「40 条用例全部读到 + 4 道闸门全部产出」。
用例未通过属预期（离线桩模型不调工具），但**崩溃必须让 CI 变红**。

### 沙箱说法自相矛盾

README 承诺「and a sandbox」，而 `SECURITY.md` 写着「there is no sandbox」。
已按代码事实统一：策略闸门 + 审批 + 默认拒绝 + 执行前检查，
**没有 OS 级沙箱**（restricted 档是「检查」不是「关住」，恒为 degraded）。

## 变更

### 宣传口径统一为「是地基，不是应用」

之前 README / README_zh / 落地页三处卖的都是「安全、幂等、可度量」——
三条关于**一次长任务**的保证。太窄，读起来像给后端团队用的 CI 器件。

现在统一为：

> **是地基，不是应用。** aicf 是 Agent 系统往下长的那一层：长期运行、持久、
> 稳定、安全、可审计 —— 从下到上，跨模态，任务需要几个 Agent 就几个。

并补上了此前三处都没提的四个维度（每条给出真实模块路径）：
全模态（`aicf/infra/resources/`）、多 Agent（`aicf/harness/agent/`、
`aicf/infra/control/identity.py`）、技能生态（`aicf/harness/skills/`）、
长期持久（`aicf/infra/runtime/`、`aicf/harness/memory/`）。

### 英文文档与英文落地页

`docs/en/` 四份（evaluation / getting-started / runtime / security）+
`docs/site/en/index.html`，另加 `docs/community.md`、`docs/skill-spec.md`。

### 徽章

- CI 徽章换成 shields.io，与其它徽章同款。
- 新增「Tests」徽章，显示**这个 commit 的真实用例数** ——
  Pages 工作流发布前真跑一遍测试，数字是当场跑出来的，不是抄来的。

### 版本一致性做成测试

`tests/test_version.py` 现在会扫描所有文档里的「当前发布版是 X」声明，
X 必须等于 pyproject 的版本；下限声明（`1.0.0 or newer`）也不能高于当前版本。
以后改了版本号忘了改文档，CI 会拦。
